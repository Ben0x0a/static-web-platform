# <App name>

<One or two sentences: what the app does and for whom.>

The app works **locally**: by default it contacts no server other than the one it is
hosted on, and it asks before any other connection. Use it as an **installable app**
(it updates itself, and works on phones), or download it as a **single HTML file** for
offline machines. It is built on
[static-web-platform](https://github.com/<owner>/static-web-platform) (`platform/`,
a Git submodule).

## Structure

```
platform/        shared platform (submodule) — never edit here
src/
  site.json      settings: id, title, language, siteUrl, download name, entry, external servers, options
  core/          pure logic and types (no page access) — tested in tests/
  data/          optional: bundled datasets + SOURCES.md (read through core/)
  state/, ui/    optional: shared state / shared display helpers
  features/      one capability each (code + CSS; a subfolder when it grows)
  workers/       optional: Web Workers (core only)
  api/           optional: the app's operations (pure), used by features/ and cli/
  cli/           optional: command-line shell over api/ (Deno)
  content.ts     content (EDIT HERE), type-checked against core/types.ts
  main.ts        wiring: starts the platform, registers the features
  app.css        theme and layout
  index.html     page shell
  icons/
tests/           unit tests of src/core/
scenarios.json   screens reached by interaction, re-checked by `swp gate`
public/          generated by `npx swp build` — committed and published as is
```

Add a feature: create `src/features/<name>.ts` (and `.css`), add its type to
`src/core/types.ts`, and register it in `src/main.ts`.

The build enforces these layers: a feature never imports another feature, `core/`
never touches the page or the platform. A new interactive screen (panel, dialog,
mode) also needs a scenario in `scenarios.json`.

## Setup (once per machine)

```bash
git submodule update --init          # fetch platform/
mise exec -- npm ci                  # pinned TypeScript, esbuild, platform
```

## Editing

1. Edit `src/` (usually `src/content.ts`).
2. `mise exec -- npx swp build`. A type error, such as a misspelt field in the
   content, stops the build with its location.
3. Run the checks (below), then commit `src/` and `public/` together.

An external server the app may contact is declared in `src/site.json` `netOrigins`.
The build then allows it in the security policy, and users are asked before it is
contacted.

## Verification

```bash
mise exec -- npm run typecheck && mise exec -- npm test
mise exec -- npx swp verify      # public/ is exactly what src/ builds to
mise exec -- npx swp gate        # security, consent, accessibility, mobile, download, offline
```
Then do the manual keyboard and screen-reader pass (`static-web-app` skill,
`references/accessibility.md`).

## Continuous integration

Every push and pull request runs `.github/workflows/ci.yml`. It fetches `platform/`
with the checkout. It installs from the lockfile, type-checks and tests, checks that `public/` is
byte-for-byte what `src/` builds to, then runs the gate in Chrome. CI never deploys.
Dependabot proposes weekly updates for the CI actions, the npm tools and the platform
submodule; rebuild `public/` in those pull requests.

## Updating the platform

```bash
git -C platform fetch --tags && git -C platform checkout vX.Y.Z
mise exec -- npx swp build && mise exec -- npx swp gate
```
Read `platform/CHANGELOG.md` first. Commit the `platform` pointer together with
`public/`.

## Deploying

Any static host can serve `public/`. On Cloudflare Pages: framework preset *None*, an
empty build command, output directory `public`. After the first deployment, set
`siteUrl` in `src/site.json` to the production URL and rebuild, so downloaded copies
can check for updates.

## Install and download

- **Install** (on the site): the app opens offline and updates itself. On iPhone: Share
  → Add to Home Screen. On Mac Safari: File → Add to Dock.
- **Download**: a local copy for machines that are offline or locked down — a single
  HTML file (or, for apps that need a real origin, a zip with a local server started
  with Deno; see its `README.txt`). In it, *Check for updates* (after your consent)
  compares it with the site. `public/version.json` lists the current version and the
  SHA-256 of each published copy.

## Command line

<Only if `src/site.json` declares `cli`; otherwise delete this section.> The same
operations as the page, for scripts and batch work, in `public/<id>-cli.js`
(*Command line* link on the site). It needs [Deno](https://deno.com) 2.9 and reads
only the files it is given; it never uses the network:

```bash
deno run --no-config --no-prompt --allow-read <id>-cli.js --help
deno run --no-config --no-prompt --allow-read <id>-cli.js <command> FILE      # JSON on standard output
```
Add `--allow-write=out.json` with `--out out.json`. Other programs can import the same
file as a library: `import { <operation> } from "./<id>-cli.js"`.

## Privacy and accessibility

No analytics, CDN or web fonts. Nothing the user enters goes into the address bar;
results can be shared only through *Share*, which shows what the link contains
before copying it. The external servers the app may contact are listed
in its *Privacy* dialog, which also allows withdrawing consent. Data entered in the app
stays in the browser of the device that entered it. The *Accessibility* panel turns
single-key shortcuts off (for voice control) and, where offered, chooses the theme.
